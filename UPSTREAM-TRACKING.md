# Upstream tracking

Where upstream and other projects stand on each thing this repository carries itself. [UPSTREAM.md](UPSTREAM.md) says *what* differs and *why*; this file says *what already exists elsewhere*, *when ours can go*, and *what we could give back*. Its purpose is to avoid parallel solutions and to drop patches as soon as upstream has them.

**How to use it**

- **Before writing a patch, driver, setting or workaround:** search for existing work beyond master: open and closed PRs, patch series on the mailing lists (U-Boot and Linux through their Patchwork APIs), maintainers' forks and branches, issue trackers, and the upstream project's own files in the pinned source. Build on what exists; add a row here either way.
- **At every version bump** of a pinned source: go through the rows for that source and check each "Drop when".
- **A row whose "Checked" date is older than three months** is checked again before anyone relies on it.
- A commit that adds, changes or drops a patch updates its row here, as it does in `UPSTREAM.md`.
- **Continuous watch:** [.github/workflows/upstream-watch.yml](.github/workflows/upstream-watch.yml) runs daily over the list in [.github/upstream-watch.json](.github/upstream-watch.json) (posted series and their review state, keyword searches for new series, PRs and issues, fork branches, master files that tell whether a patch is still needed, new releases). Changes are posted to the GitHub issue labelled `upstream-watch` and mark it `upstream-change`; a Claude session in this repository is told at start (.claude/hooks/upstream-watch-check.sh), updates the rows here and removes the label. A new row here gets an entry in the watch list.

States used: **in master** (upstream has it), **in review** (posted, not merged), **in a fork/branch**, **unposted** (exists nowhere we found), **not checked yet**.

Where to search: U-Boot `https://patchwork.ozlabs.org/api/patches/?project=uboot&q=<words>`; Linux `https://patchwork.kernel.org/api/patches/?project=<linux-arm-kernel|devicetree|netdev|...>&q=<words>` (q matches subjects); GitHub mirrors of U-Boot and Linux master; `gh pr list` / `gh issue list --state all --search` for GitHub projects. lore.kernel.org and git.kernel.org refuse automated reads.
